# 五分钟演示

当前机器已经部署，打开http://127.0.0.1:18190/，点击左侧“开始使用”。演示调查与核验为明确标注的可控测试响应，状态、任务、原文和业务探针是真实的；真实模型调用0次。3.2正式评测另保留真实模型结果。

## 维护者准备（用户验收不必执行）

```powershell
./scripts/local/Start.ps1 -Scope Platform
./scripts/local/Demo.ps1
```

仅重启平台，准备独立故障实验的worker停止和排队任务；不覆盖历史案例指针。脚本拒绝与未完成调查/执行中恢复同时准备。已有可用语义索引用于锁定资料版本，手册读取走关键词检索，不调用模型。缺少索引时保持错误提示，需先完成知识库设置。

需要做技术自检时，维护者使用Demo.ps1 -SelfCheck，它明确以development_selfcheck批准一份方案并验证真实业务，然后再次运行普通Demo.ps1留下待用户批准的新调查。普通准备不会批准恢复。默认不生成有有效期的方案，用户点击时才生成十分钟方案。

## 演示顺序

1. “打开成功调查”：看到worker已停止、指定任务排队、数据库/Redis可达、手册机制，点引用打开原文。强调报告中的响应来源是可控演示。
2. 回“开始使用”→“审阅并生成恢复方案”，确认所选调查是3.3闭环演示，点击生成（不执行）。检查目标仅故障实例、动作仅启动worker，批准前动作记录0条。
3. 勾选批准并执行。预期worker启动，新任务completed，字符31、词5，动作记录1条。刷新或只读复核不发第二条动作。
4. “打开信息不足调查”：未连接实例缺少运行资料，没有根因，明确需要补充状态/日志/脱敏配置与任务；恢复方案接口拒绝此记录。
5. “打开对照评测”：选择正式报告，查看528条及真实失败；查找框输入wrong_version-03，直接打开单/多案例。

## 演示后的状态

成功批准后故障worker为运行；信息不足演示不改任何服务。再次演示需维护者重新准备，它会生成新调查而不删除旧历史。正常实例或项目一维持原状态，不要求为本演示启动它们。方案因状态变化失效时重新核对，不把历史证据当当前状态强行恢复。
